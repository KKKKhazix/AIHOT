## 数据怎样组织

| 表 | 用途 |
|---|---|
| `ep_products` | 区分平台、导管、发生器、标测系统等身份；本次不开发别名引擎。 |
| `ep_studies` | 研究身份及注明来源、口径和时间的总体信息；不向结果自动分配分母。 |
| `ep_research_records` | 文献身份、来源版本、材料范围、公开状态和私有处理记录。 |
| `ep_record_studies` | 可选的多对多关联，允许无注册号病例和多个研究的汇总报告。 |
| `ep_research_arms` | 本篇报告内的组别和可选的组别样本口径。 |
| `ep_research_contexts` | 明确同时成立的产品使用场景、疾病、影像及射线策略。 |
| `ep_context_products` | 场景内产品及其角色。不因文章里同时出现就认定组合使用。 |
| `ep_research_findings` | 具体观察、独立分母、观察时间、原文位置和公开许可。 |

场景比组别更细。同一组里不同患者、不同操作使用不同组合时，应建立不同场景；没有依据证明条件共同成立时，不应建立强关联。保存层可以保护关系不被串接，但不能判定人工或未来模型提供的关联是否真实，后续提取验收仍然必要。

一条结果的时间与终点共同保存。七天安全观察不借用另一个终点的一年随访，入组期间不参与随访筛选。查询默认不把“计划随访”当“已观察到的随访”；调用方必须明确所需口径。

一年和十二个日历月、一个星期和七天可以精确归入各自比较组；本次不把日数擅自换算成日历月。365天与12个月暂不作为完全匹配，可能需要在后续产品中作为明确标注的相关结果呈现。这是保守的已知限制，不是表示两者临床意义完全不同。

`numerator/denominator` 当前表达计数比例，不能存入重复事件/人年发生率、风险比或置信区间后假装已经支持。其他统计量可以保留私有材料，但需明确扩展结构后才能进入数值查询。

## 保存与重复导入

`saveResearchRecord` 先完成运行时验证，再在一个事务内保存记录、组别、场景、产品关系和结果。原文来源和版本都是必填；实际全文下载不在本次范围。

DOI 使用规范化身份。同一份规范化输入重复提交时返回已有 ID，不重复插入子记录。已有 DOI 的内容、权限、版本或字段发生变化时，本次返回 `ResearchImportConflict`，不静默覆盖，也不创建模型任务。没有 DOI 时依赖调用方提供的稳定 `sourceKey`。多来源同 DOI 的来源补充与历史版本管理尚未实现，冲突应保留给显式修订流程。

产品与研究词表也是显式、插入优先的管理操作，不让模型自动合并。母研究信息、组别人数和单项结果分母完全独立。缺失数据保持缺失。

## 公开读取

新增 `publication/research.ts`，继续遵守原仓库统一公开读取层。它只读取四个白名单视图，不读取私有正文、证据引文、内部备注、处理版本或母研究人数。

公开许可分为文献元数据、场景字段组和具体结果三层。场景许可批准的是这组明确字段及其关联的基础组别信息；结果许可批准的是该项结果的展示字段。不能只隐藏字段，却仍用它匹配搜索。隐藏的场景或结果不会进入公开筛选。

许可记录是操作配置，不是法律意见或自动授权判断。公开状态默认为关闭；撤回或过期后所有新研究读取均排除该记录。权限检查没有意味着数据库管理员不能直接查看基础表，仍需按部署要求配置账号权限。

本次未接通网页、RSS、API、MCP 或外部缓存，不能据此宣称所有线上出口的权限测试已经通过。以后接通时必须统一调用公开读取层，并另测缓存清理和各出口。

## 查询边界

只支持受控结构化条件：产品 ID、疾病、影像、射线策略、研究对象、设计、终点和带明确口径的随访阈值。没有模型生成 SQL，也没有自由文本解释。

全部条件绑定为参数；产品、影像和疾病在同一场景内校验；终点和随访在同一结果内校验。返回实际匹配的场景和结果，避免页面展示一个脱离条件的“最长随访”。

按日期和 ID 做游标分页，不用深 OFFSET。先取得有限的记录页，再取匹配详情。索引是设计候选，实际性能仍以数据库执行计划和真实规模测试为准。

## 在实际工程验证

前提：Node >=24.11、上游工作区依赖已经安装、一个独立 PostgreSQL 17 测试库，数据库名以 `_test` 或 `_ci` 结尾。不得使用生产数据库。测试 URL 不允许 query 参数覆盖数据库或 search_path。

Windows PowerShell 示例（替换测试数据库凭据，不要粘贴生产凭据）：

```powershell
$env:DATABASE_URL = "postgres://TEST_USER:TEST_PASSWORD@127.0.0.1:5432/ep_pr1_test"
$env:EP_PR1_REPORT_DIR = ".data/ep-pr1"
node scripts/ep-pr1-check.ts
npm run typecheck
```

Linux/macOS 示例：

```bash
DATABASE_URL='postgres://TEST_USER:TEST_PASSWORD@127.0.0.1:5432/ep_pr1_test' \
EP_PR1_REPORT_DIR='.data/ep-pr1' node scripts/ep-pr1-check.ts
npm run typecheck
```

脚本在子进程关闭采集、模型和通知，使用原迁移器的迁移账本，再运行本次两组测试。不会启动 worker 或服务，不会读取 `.env`。测试目标默认为本机；确需远程独立测试库时，另外明确设置 `EP_PR1_ALLOW_REMOTE_TEST_DB=1`，仍不能使用生产库。

真实数据库测试不提供模拟回退，也不会在缺数据库时显示通过。测试只清理自己这次随机前缀的数据，不清空上游业务表。合并评审应同时查看 PR1 验收、基线对照和上述未消除的原有回归阻断；若合并门禁要求全绿，还需要先修复该门禁环境或上游测试。

`EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` 在测试成功时写入报告目录。它是小规模固定材料的真实执行计划，不是吞吐量测试，也不保证万篇资料下的延迟。

## 六项最低验收

没有注册号的病例可独立保存；重复 DOI 不重复建档；多研究组与多场景条件不串接；总体人数不自动变成终点分母；零射线策略与完成比例分开；未公开字段不能通过正文或筛选泄漏。

额外测试包括并发幂等导入、事务失败回滚、数据库外键与 CHECK、过期撤回、SQL 参数化和分页。不以“测试文件已写好”等同于“测试通过”。
