
【标题自洽规则 — 让读者不点开就知道"这是关于谁的什么事"】

1. 标题必须点出核心主体：社区名 / 机构名 / 政策名 / 场景名 / 活动名。
2. 原标题已经清楚点出主体的：英文标题翻译成中文、中文标题保持原意，不要为改写而改写。
3. 原标题只是日期 / 序号 / 没信息量的 teaser（如 "11.10"、"第二期"、"重磅发布"）时，结合【来源】和正文把主体补进标题。例：原标题 "11.10" + 来源 "新武安" → "武安发布首批 50 个 OPC 应用场景"。
4. 补主体只能用【来源】或正文里真实出现的名字。正文和来源都没点出具体社区或机构时，用上位词（如"某县 OPC 社区"）兜底，绝不凭"行业常识"编一个具体名称 / 数字 / 日期。
5. 原标题表达的【文章类型和核心动作】是硬边界：How / Why / Guide / Analysis / Review 这类解释、分析或教程标题，中文标题必须保留这个类型；不能因为正文谈到一个已经存在的政策、场景或活动，就改写成“发布 / 推出 / 启动”。只有原标题明确宣布了发布、推出、启动或招募，中文标题才能使用对应动作。保留文章类型不等于删主体：仍须按第 1-4 条补全正文或来源明确给出的社区、机构、政策或活动名称。
   例：原标题 "How to register an OPC in Handan" → "邯郸 OPC 注册流程：如何完成企业开办"，不能写成 "邯郸发布 OPC 注册新政"。
   例：原标题 "How to apply for the compute voucher" + 来源和正文明确是广平县 → "广平 OPC 算力券如何申领"，不能只写成缺主体的 "如何申领算力券"。
6. 本条的动作和背景里的旧发布要分清：原文把发布写成过去的事（“At the launch event, we introduced …”“Last week we launched …”“上周我们发布了…”），本条是在讲用法、做演示或再次推广时，标题写介绍、演示或讲解，把发布交代成此前的事；不能写成“推出 / 发布 / 上线”，否则读者会当成今天的新闻。只有原文明确某项政策、场景或活动是现在才开放或新增，才对那一项用对应动作。
   例：正文 "At the summit, we introduced the 50-scenario list … See how to apply below" → "武安演示 50 个场景清单的申报用法"，不能写成 "武安在发布会推出 50 个场景"。
